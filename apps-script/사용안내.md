# 일기 구글 시트 CRUD 스크립트

공유받은 스프레드시트의 첫 번째 시트에서 `timestamp`, `datetime`, `content` 헤더를 찾아 일기를 조회·생성·수정·삭제하는 Apps Script입니다. 헤더는 첫 번째 행에 있어야 하며, 열 순서는 달라도 됩니다.

## 설치 방법

1. 구글 시트를 열고 **확장 프로그램 → Apps Script**를 선택합니다.
2. 편집기의 `Code.gs` 내용을 이 폴더의 `Code.gs` 내용으로 바꿉니다.
3. 저장한 뒤 스크립트를 한 번 실행하고, 시트 접근 권한을 승인합니다.
4. 웹 API로 사용할 경우 **배포 → 새 배포 → 웹 앱**을 선택해 배포합니다.
5. 일기 내용은 개인 정보일 수 있으므로 웹 앱 접근 권한을 필요한 사용자로 제한합니다. 공개 링크로 배포하지 마세요.

이 스크립트는 시트의 첫 번째 탭을 사용합니다. 다른 탭이 대상이면 `getDiaryTable_()` 안의 시트 선택 코드를 해당 탭 이름에 맞게 바꿔 주세요.

## 일기 앱 연결

웹 앱 배포가 끝나면 배포 URL을 프로젝트의 `.env.local` 파일에 `NEXT_PUBLIC_GOOGLE_SCRIPT_URL` 값으로 설정합니다. 개발 서버를 다시 시작하면 앱의 `저장` 버튼이 일기를 생성하거나 수정하고, `일기보기` 버튼이 목록을 불러옵니다. 목록의 `수정`과 `삭제`도 같은 Apps Script를 통해 처리합니다. 앱은 브라우저에서 Google 주소를 직접 호출하지 않고 `/api/diaries` 서버 경로를 거칩니다.

앱과 Apps Script가 서로 통신하려면 웹 앱 배포 설정에서 서버 요청이 허용되어야 합니다. 일기에는 개인 정보가 들어갈 수 있으므로 익명 공개 배포는 피하고, 공개 서비스로 배포하기 전에는 사용자 인증 또는 공유 토큰을 추가해야 합니다.

## 요청 규격

웹 앱 URL을 `웹 앱 주소`라고 할 때, 응답은 `{ "success": true, "data": ... }` 또는 오류 정보를 담은 JSON입니다.

### 전체 조회

`GET 웹 앱 주소?action=list`

### 한 건 조회

`GET 웹 앱 주소?action=get&timestamp=행의timestamp값`

### 생성

`POST 웹 앱 주소`에 다음 JSON을 전송합니다. `timestamp`는 스크립트가 생성합니다.

```json
{
  "action": "create",
  "data": {
    "datetime": "2026-10-08T14:30:00+09:00",
    "content": "오늘 기록한 일기"
  }
}
```

`datetime`을 생략하면 생성 시각을 ISO 형식으로 기록합니다.

### 수정

```json
{
  "action": "update",
  "timestamp": "생성 응답에서 받은 timestamp",
  "data": {
    "datetime": "2026-10-08T15:00:00+09:00",
    "content": "수정한 일기 내용"
  }
}
```

수정할 필드만 `data`에 보낼 수 있습니다. `timestamp`는 행 식별자로 사용되므로 수정되지 않습니다.

### 삭제

```json
{
  "action": "delete",
  "timestamp": "삭제할 행의 timestamp"
}
```

현재 스크립트는 Apps Script 소스 파일과 안내를 생성한 상태입니다. 구글 계정의 Apps Script 편집기에 설치하거나 웹 앱으로 배포하지는 않았습니다.
